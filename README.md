# 秋招画像系统

面向应届生的求职信息管理工具。**填一次信息，覆盖央国企 + 互联网双赛道网申**，并自动生成能力画像与岗位匹配推荐。

> 🔒 **隐私声明：所有数据仅保存在你自己的浏览器中，不会上传到任何服务器。**
> 本项目没有后端、没有数据库、没有账号系统。开发者看不到、也无法获取你填写的任何信息。

---

## 快速开始

### 方式一：GitHub Pages（推荐）

访问部署地址即可，无需安装任何东西。

### 方式二：本地运行

```bash
# 1. 进入项目目录
cd qiuzhao-2027

# 2. 启动本地 HTTP 服务器（Python 3）
python -m http.server 8765

# 3. 浏览器访问
open http://localhost:8765
```

> ⚠️ **不要直接双击 `index.html` 用浏览器打开。** 岗位匹配页（`match.html`）使用 `fetch` 加载 `jobs/jd-library.json`，在 `file://` 协议下会因浏览器 CORS 限制而报错。必须通过 HTTP 服务器访问。

## 三阶段工作流

| 阶段 | 页面 | 功能 |
| --- | --- | --- |
| **信息填写** | `index.html` | 87 字段档案，覆盖互联网 + 央国企双赛道网申 |
| **能力画像** | `portrait.html` | 7 维雷达评分 + 角色适配 + 优势短板 + 可编辑校准 |
| **岗位匹配** | `match.html` | 六维加权匹配 + 实时筛选 + 标记投递 + 导出 |
| **意向岗位** | `intention.html` | 意向管理 + 三档分析 + 对话式经历挖掘 |
| **简历生成** | `resume.html` | 一键生成完整简历 + ATS 兼容性校验 |

三页之间通过顶栏按钮自然导航，数据自动通过 localStorage 流转，无需手动导入导出。

## 它解决什么问题

秋招要填的信息又多又重复：

- 互联网网申问 GitHub、技术栈、项目难点
- 央国企网申问民族、籍贯、政治面貌、家庭情况、学生干部经历
- 每换一家公司，同样的信息重填一遍

这个工具让你**一次性把所有字段填全**，之后：

- 需要填网申时，打开档案照抄
- 需要做简历时，按投递对象自动取舍内容
- 需要选岗位时，系统基于你的画像自动推荐 + 给出差距分析

### 设计特点

**按赛道动态显示字段。** 只投互联网就不会看到"家庭主要成员"；勾了央国企才出现民族、籍贯、政治面貌等网申必填项。目前共 87 个字段，实际显示 63–87 个不等。

**三档技能分级。** 强制把技能分成"熟练 / 熟悉 / 了解 / 缺口"四档，只有"熟练"档才建议写进简历。这是防止面试被问倒的关键设计。

**记录短板。** 每段实习和项目都有一个"⚠️ 我讲不清楚的地方"字段。它不会出现在简历里，但面试准备时会用到——诚实记录短板比假装没有更有用。

**不鼓励编造。** 量化成果一栏明确提示"没有真实数字就写暂无量化，不要估算"。简历里的每个数字面试官都可能追问。

## 数据怎么存、怎么带走

| 机制 | 说明 |
| --- | --- |
| **自动暂存** | 每次修改后自动存入浏览器 localStorage，刷新页面不丢 |
| **导出 JSON** | 点右上角"导出 JSON"，得到一个完整档案文件 |
| **导入 JSON** | 换电脑/换浏览器时，点"导入 JSON"选择文件即可完整恢复 |

### ⚠️ 重要提醒

localStorage 是**按域名和协议隔离**的，意味着：

- 线上填的数据，本地打开时看不到（反之亦然）
- 清理浏览器缓存会清空数据
- 换设备、换浏览器不会自动同步

**所以导出的 JSON 文件才是你的唯一可靠备份，请务必妥善保管。** 建议每次填完都导出一次。

### 敏感字段的特殊处理

身份证号、紧急联系人、家庭成员这三项标记为 🔒，导出时会单独放进 `_sensitive` 字段：

```json
{
  "name": "张三",
  "phone": "138...",
  "_sensitive": {
    "idNumber": "...",
    "familyMembers": "..."
  }
}
```

如果你要把档案发给别人看（比如找人帮忙改简历），**先手动删掉 `_sensitive` 这一段**即可。导入时如果有这段会自动还原。

## 版本兼容

字段 schema 遵循**只增不改**原则：新版本只添加字段，不重命名或删除已有字段。

导入旧版本导出的文件时，系统会自动补齐缺失的新字段并保留所有旧数据，不会因为版本不同而报错或丢数据。已测试 v1 档案可正常导入 v3。

### 加字段 / 改字段

只需编辑 `src/schema.js`。字段定义示例：

```js
{
  key: 'github',
  label: 'GitHub 主页',
  type: 'text',                    // text|textarea|number|month|select|radio|multiselect|checkbox
  required: false,
  track: 'internet',               // soe|internet|both（仅用于显示标签）
  showIf: d => hasTrack(d, '互联网大厂'),   // 条件显示
  hint: '没有可留空',
  sensitive: false                 // true 则导出时隔离到 _sensitive
}
```

改完刷新浏览器即可看到效果，不需要构建。

**修改 schema 时请遵守：只增不改。** 如果重命名了已有字段的 `key`，用户之前导出的档案就会丢失那部分数据。确实需要替换时，加新字段并保留旧字段。

### 加岗位 / 加方向

详见 `jobs/README.md`。简要说明：

- **同方向扩量**：直接往 `jd-library.json` 的 `jobs` 数组追加，无需改代码
- **新增方向**：改 `jd-library.json` + `src/match-engine.js` 的 `TRACK_REGISTRY` + 可选改 `schema.js` 和 `portrait-engine.js`

### ⚠️ 请保留隐私防护

本项目会收集个人信息。如果你 fork 后要公开发布，请保留：

1. **`.gitignore` 中的个人数据规则** —— 防止档案文件被提交
2. **`tools/install-hooks.ps1`** —— 安装后会在 commit 前扫描手机号、身份证号并阻止提交

安装钩子：

```powershell
powershell -ExecutionPolicy Bypass -File tools\install-hooks.ps1
```

公开仓库一旦提交了个人数据，**Git 历史里会永久留存，删掉文件也无法真正清除**，且任何 fork 的人都能拿到。这两层防护拦得住意外，请不要移除。

## 部署到 GitHub Pages

1. 把代码推到 GitHub 仓库
2. 仓库 Settings → Pages → Source 选 `main` 分支根目录
3. 等一两分钟，访问 `https://<用户名>.github.io/<仓库名>/`

因为是纯静态页面，不需要任何构建步骤。注意 GitHub Pages 默认使用 HTTPS，与本地 HTTP 的 localStorage 不互通。

## 技术说明

纯静态站点，Vue 3（CDN 版本，已下载到本地）。无构建流程、无 npm 依赖、无后端。

选择这个方案是因为：字段多且条件逻辑复杂，纯手写 DOM 操作难以维护；但引入完整构建工具链又会抬高使用和贡献门槛。CDN 版 Vue 是这个规模下的平衡点。
