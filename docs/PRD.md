## 一、产品概述

### 1.1 产品定位

秋招画像系统是一款面向应届生的求职信息管理工具。它解决的核心痛点是：秋招过程中信息填写重复、简历与岗位不匹配、经历不知如何包装。

产品以"填一次，管全程"为设计理念，覆盖从信息归档、能力画像、岗位匹配到简历生成的完整求职链路。

### 1.2 核心价值主张

- **信息只填一次**：87 个字段覆盖互联网与央国企双赛道网申，之后照抄即可
- **岗位主动推荐**：基于画像自动匹配岗位，不再海投
- **经历智能挖掘**：把"做过的事"翻译成"JD 想看到的话"
- **简历一键生成**：按投递对象自动取舍内容，生成完整简历
- **数据完全私有**：纯前端实现，所有数据仅存浏览器，不上传服务器

### 1.3 与现有方案的区别

| 维度 | 传统网申 | 简历模板网站 | 秋招画像系统 |
|------|----------|-------------|-------------|
| 信息复用 | 每家公司重填 | 只填简历 | 覆盖网申 + 简历 + 画像 |
| 岗位匹配 | 无 | 无 | 六维评分自动推荐 |
| 经历挖掘 | 无 | 无 | 对话式 STAR 文案生成 |
| 数据隐私 | 上传至公司服务器 | 上传至平台 | 纯本地，不上传 |
| 双赛道适配 | 无 | 无 | 互联网 / 央国企字段动态切换 |

## 二、目标用户与用户场景

### 2.1 用户画像

**主要用户：2027 届应届毕业生**

- 学历层次：本科、硕士、博士
- 目标行业：互联网大厂、央国企、外企、中小厂/创业公司、事业单位/高校
- 技术背景：数据类、产品类、技术类、运营类
- 求职阶段：暑期实习转正、秋招正式批、春招补录

### 2.2 核心场景

**场景一：网申填写**

> 小张在投递美团数据分析师岗位时，网申系统要求填写：最高学历、毕业时间、GitHub 主页、实习经历、项目难点、技术栈。两天后投递某央企时，又要求填写：民族、籍贯、政治面貌、家庭主要成员及工作单位、学生干部经历、奖惩情况。
>
> 使用秋招画像系统后，小张在信息填写页一次性录入全部 87 个字段。之后每次网申只需打开档案，复制粘贴对应字段即可。

**场景二：岗位选择**

> 小李投了 50 家公司但回复寥寥，不清楚自己的背景适合哪些岗位。她在系统中填写完档案后，岗位匹配页自动推荐了 12 个高匹配度岗位，并给出了每家的缺口分析——"你的指标体系经验与这个岗位匹配度 92%，但用户增长经验缺失，建议补充相关项目"。

**场景三：简历优化**

> 小王有美团数据分析实习经历，原始描述是"独立设计活动效果评估指标体系"。他投字节的一个要求"AB 实验"的岗位时，系统通过对话式挖掘引导他补充了实验细节，最终生成 STAR 格式文案："设计对照实验评估两种运营策略效果，覆盖 5 万用户，验证策略 A 转化率较基准提升 50%，驱动策略迭代上线。"

**场景四：简历生成**

> 小赵需要给不同公司投不同版本的简历。她在系统中标记了 5 个意向岗位，简历生成页自动按每个岗位的要求取舍内容：投互联网时突出技术栈和项目难点，投央国企时突出学生干部和荣誉奖项，并自动生成完整简历文本。

## 三、核心功能模块

### 3.1 信息填写（index.html）

#### 功能描述

提供分步向导式表单，引导用户录入完整的求职档案。共 10 个章节、87 个字段。

#### 字段分类

| 章节 | 字段数 | 说明 |
|------|--------|------|
| 开始之前 | 3 | 目标赛道、最高学历、毕业年份 |
| 基本信息 | 12 | 姓名、手机、邮箱、GitHub 等 |
| 教育背景 | 8 | 学校、专业、GPA、荣誉等 |
| 求职意向 | 10 | 目标城市、目标岗位、期望薪资等 |
| 实习经历 | 12/段 | 公司、岗位、时间、职责、成果、短板等 |
| 项目经历 | 12/段 | 项目名称、角色、技术栈、难点、成果等 |
| 技能清单 | 8 | 熟练 / 熟悉 / 了解 / 缺口 四档分级 |
| 荣誉奖励 | 4 | 奖项名称、级别、时间、证明链接 |
| 自我评价 | 3 | 优势总结、短板反思、职业规划 |
| 敏感信息 | 15 | 身份证号、家庭成员等（仅央国企需要） |

#### 关键设计

- **动态字段显示**：根据"目标赛道"选择，自动显示/隐藏相关字段
- **条件触发**：勾了"央国企"才显示民族、籍贯、政治面貌等字段
- **自动暂存**：每次修改后自动存入 localStorage
- **导入导出**：支持 JSON 格式的完整档案备份与恢复
- **敏感字段隔离**：身份证号等字段导出时单独放入 `_sensitive` 对象

#### 版本兼容

字段 schema 遵循"只增不改"原则。旧版本档案导入时，系统自动补齐缺失的新字段并保留所有旧数据。

### 3.2 岗位匹配（match.html）

#### 功能描述

基于用户画像，从 JD 库中筛选并排序最匹配的岗位，提供多维度筛选和配置能力。

#### 核心能力

**六维匹配评分**

| 维度 | 权重 | 说明 |
|------|------|------|
| 方向匹配 | 30% | 用户目标方向与岗位方向的吻合度 |
| 技能覆盖 | 25% | 用户技能与 JD 要求的重叠度 |
| 经历相关 | 20% | 实习/项目经历与岗位业务的相关性 |
| 学历匹配 | 10% | 学历层次与岗位要求的匹配度 |
| 城市偏好 | 10% | 用户目标城市与岗位城市的匹配度 |
| 公司偏好 | 5% | 用户目标公司层级与岗位公司的匹配度 |

**筛选器**

- 就业类型：正式 / 实习
- 目标人群：应届生 / 实习生 / 不限
- 岗位方向：数据分析 / 商业分析 / 产品经理等
- 城市：北京 / 上海 / 深圳 / 杭州等
- 公司：字节 / 美团 / 腾讯 / 阿里等
- 匹配度阈值：高匹配（80%+）/ 中匹配（60-80%）/ 低匹配（60% 以下）

**岗位卡片信息**

- 公司名称与 logo
- 岗位名称与方向
- 匹配分数与匹配等级（高/中/低）
- 工作城市
- 岗位职责摘要
- 操作按钮：查看详情、标记投递、标记意向

#### 数据输入

- 用户画像（来自 localStorage）
- JD 库（`jobs/jd-library.json`，支持动态扩展）

### 3.3 意向岗位与经历挖掘（intention.html）

#### 功能描述

管理用户标记为"意向"的岗位，对每个岗位进行经历挖掘，生成可直接放入简历的 STAR 格式文案。

#### 核心能力

**三档经历分析**

对每个意向岗位，系统分析其 JD 关键词与用户经历的匹配关系，分为三档：

| 档位 | 说明 | 系统行为 |
|------|------|----------|
| 已覆盖 | 技能表已标注或经历文本已体现 | 建议换个说法突出 |
| 可挖掘 | 经历有相关痕迹但表述不够 JD 化 | 进入对话式挖掘 |
| 完全缺失 | 经历中未找到相关痕迹 | 建议补充相关项目或学习 |

**对话式经历挖掘**

针对每个"可挖掘"的关键词，系统通过 3-5 轮问答引导用户补充细节：

1. 确认是否做过相关事情（选择题）
2. 询问具体数据（样本量、转化率、提升幅度等）
3. 询问使用的工具和方法
4. 询问业务影响和决策推动

**STAR 文案生成**

基于用户回答，自动组装成 STAR 格式 bullet point：

```
设计对照实验评估两种运营策略效果（Situation+Task），
覆盖 5 万用户（Action），
验证策略 A 转化率较基准提升 50%（Result）。
```

**文案管理**

- 生成后可直接采用、编辑修改或重新回答
- 保存后的文案关联到对应经历项，参与后续简历生成
- 在信息填写页可查看和管理已挖掘文案

### 3.4 能力画像（portrait.html）

#### 功能描述

基于用户档案自动生成可视化能力画像，帮助用户了解自己的优势、短板和适合的岗位类型。

#### 核心能力

**七维雷达图**

- 数据分析能力
- 商业理解能力
- 技术实现能力
- 沟通表达能力
- 项目管理能力
- 学习能力
- 行业认知能力

**角色适配矩阵**

基于画像匹配最适合的岗位角色：

| 角色 | 特征 | 示例岗位 |
|------|------|----------|
| 数据分析师 | 强数据 + 强商业 | 字节数据分析师 |
| 商业分析师 | 强商业 + 中数据 | 美团商业分析 |
| 产品经理 | 强沟通 + 强商业 | 腾讯产品经理 |
| 算法工程师 | 强技术 + 强数据 | 阿里算法工程师 |

**优势与短板分析**

- 优势：基于经历中出现的高频关键词和量化成果自动提取
- 短板：基于技能缺口和"我讲不清楚的地方"字段自动提取
- 投递策略建议：根据优势短板给出投递优先级建议

**自定义校准**

用户可手动调整雷达图各维度的评分，系统会记住偏好并影响后续匹配结果。

### 3.5 简历生成（resume.html）

#### 功能描述

基于用户档案和意向岗位，一键生成完整简历文本，支持 ATS 兼容性校验。

#### 核心能力

**三源装配**

简历内容来自三个来源：

1. **基础信息**：姓名、联系方式、教育背景（来自档案）
2. **经历摘要**：实习/项目经历，按岗位要求动态取舍
3. **挖掘文案**：意向岗位对应的 STAR 文案

**加权裁剪**

根据投递对象自动调整内容权重：

- 投互联网：突出技术栈、项目难点、GitHub
- 投央国企：突出学生干部、荣誉奖项、政治面貌
- 投外企：突出英语能力、国际经历

**四态审计**

简历生成前自动检查四项合规性：

1. 信息完整度：必填字段是否已填
2. 量化比例：是否有足够的量化成果
3. 技能一致性：简历中提到的技能是否与技能表一致
4. 长度适中：简历是否在一页以内

**ATS 兼容性校验**

- 检查是否包含 JD 关键词
- 检查格式是否容易被 ATS 系统解析
- 给出优化建议

**导出格式**

- 纯文本（可直接粘贴到网申系统）
- Markdown（可转 PDF 或 Word）
- 打印优化版（隐藏按钮和导航，适合打印）

## 五、页面流程

### 5.1 主流程

```
开始
  │
  ▼
信息填写（index.html）
  │ 填写基础档案
  ▼
岗位匹配（match.html）
  │ 浏览推荐岗位，标记意向
  ▼
意向岗位（intention.html）
  │ 经历挖掘，生成文案
  ▼
简历生成（resume.html）
  │ 生成并导出简历
  ▼
投递
```

### 5.2 支线流程

**查看画像**：信息填写完成后可直接查看能力画像，了解自身优势短板。

**导入/导出**：任何页面都可以导入历史档案或导出当前档案备份。

**演示模式**：任何页面都可以加 `?demo=1` 参数进入演示模式，使用虚构数据。

## 六、非功能需求

### 6.1 性能

- 首屏加载时间 < 2 秒（所有资源本地托管）
- 表单操作响应 < 100ms
- 岗位匹配计算 < 500ms（本地计算，无网络请求）

### 6.2 兼容性

- 浏览器：Chrome 90+ / Edge 90+ / Firefox 88+ / Safari 14+
- 移动端：支持响应式布局，核心功能在移动端可用
- 离线：所有资源本地托管，无网络时仍可正常使用（除岗位数据需首次加载）

### 6.3 隐私与安全

- 所有用户数据仅存 localStorage，不上传服务器
- 敏感字段导出时隔离到 `_sensitive`
- Git 钩子防止个人数据意外提交
- 无 Cookie、无追踪脚本、无第三方服务

### 6.4 可维护性

- 字段 schema 只增不改，保证版本兼容
- 模块分离：schema / 引擎 / UI 三层独立
- 无构建流程，改完刷新即生效
