# GiveMeOC 集成修正实施计划

按 P0、P1、P2 顺序执行。项目没有 Git 元数据，因此不创建 Git 仓库或 worktree；不覆盖已有增强库、个人数据、投递记录或源工作簿。每个功能先增加能失败的针对性测试，再实现并运行测试。

## P0：岗位库与匹配可信度

1. [x] 新建岗位库单元测试：必需内置库失败时拒绝加载；可选增强库缺失时继续；按 ID 合并且增强记录优先；旧意向快照和元数据回退可恢复。
2. [x] 实现共享加载与意向解析模块，并用它替换 match、intention、resume 页面重复加载逻辑。
3. [x] 新建匹配引擎回归测试：职位列表无职责/关键词时技能和经验维度不可用、缺口为空、覆盖率下降；公司未知时企业维度不可用；完整 JD 仍按原权重评分。
4. [x] 实现仅用可用维度重归一化的评分和覆盖率/资料有限状态；更新三页面徽标、详情与简历评估闸门。
5. [x] 更新意向页：无关键词时显示不可挖掘说明，不显示 0/0 进度或空的挖掘交互；匹配详情修复空链接和显示截止日期、来源类别。

## P1：源表转换与事实型简历文案

1. [x] 为转换脚本增加临时合成 xlsx 的单元测试：每个岗位片段独立分类、保留公司类型和源片段、分隔行为、截止过滤和稳定 ID；投递入口和截止相同的跨地点职位合并地点，二者不同则分开。
2. [x] 重构转换脚本为可导入纯函数与 CLI；增加输入/输出参数，并将默认路径改为脚本相对路径。测试输出仅写入临时目录。
3. [x] 为 GiveMeOC 抓取脚本增加路径参数和脚本相对默认值；不调用网络抓取。
4. [x] 为文案生成器增加测试：空答案和部分答案不能出现编造的数量、指标、提升、影响、工具或协作方；完整事实仍正确进入结果。
5. [x] 修正模板变量选择和 UI 的来源信息、截止日期及无入口状态。

## P2：文档收尾

1. [x] 更新 README、岗位库说明和交付说明中的旧计数/过期路径，标注数据快照日期及可复现命令。
2. [x] 写明浏览器本地存储的隐私边界与需要人工核实的来源条款。
3. [x] 复查改动文件清单，确认没有写入个人档案、缓存、源 xlsx 或增强库。

## 复核清单

- [x] 三个 UI 页面不再各自只加载内置库。
- [x] 旧 ID 意向缺失库记录时仍可显示并有明确的数据限制。
- [x] 假完整度和假关键词不会影响评分、挖掘或简历。
- [x] 转换输出在临时文件上具备稳定 ID 和可移植路径。
- [x] 文案只复述用户事实，不用默认占位内容陈述成效。
- [x] 文档准确区分项目文件可证明的事实与外部待核实状态。
